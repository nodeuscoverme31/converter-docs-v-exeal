## UX Outcomes

### UXO-001 — Пользователь понимает, как начать без инструкции
Пользователь сразу видит, что программе нужен один Word-файл `.doc` или `.docx`. Доступны два равноправных способа: перетащить файл в окно или выбрать его через системный диалог.

Источник: SC-001, REQ-001, QREQ-005.

### UXO-002 — Пользователь понимает, какой файл будет преобразован
После выбора до начала преобразования интерфейс показывает имя выбранного файла и главное действие `Преобразовать в Excel`.

Источник: REQ-001, RULE-WRITE-001.

### UXO-003 — Пользователь не принимает технических решений
После выбора файла не требуется настраивать типы данных, формат таблиц, обработку merged cells или другие технические параметры.

Источник: SC-001, RULE-MINIMAL-001.

### UXO-004 — Итог нельзя понять неправильно
После обработки интерфейс показывает ровно один из трёх статусов:
- `Готово`
- `Готово с предупреждениями`
- `Не удалось преобразовать`

Источник: SC-004, REQ-008, REQ-009, REQ-010, QREQ-001.

### UXO-005 — Результат легко найти
После успешной обработки пользователь видит фактическое имя созданного `.xlsx`, место сохранения и действие `Открыть папку`.

Источник: REQ-002, SC-001.

### UXO-006 — Предупреждения понятны
Если есть неподдерживаемый объект или неоднозначная структура, пользователь видит краткое объяснение и может раскрыть детали. Предупреждение не скрывается в техническом логе.

Источник: REQ-004, REQ-008, REQ-009, QREQ-001.

## Information Architecture

MVP использует одну основную поверхность без постоянной навигации и без wizard.

Пользовательские сущности:
1. **Исходный Word-файл** — имя, тип, состояние выбора.
2. **Преобразование** — не начато / выполняется / завершено / с предупреждениями / ошибка.
3. **Excel-результат** — имя и расположение `.xlsx`.
4. **Предупреждения** — то, что не позволяет считать перенос полностью безусловным.
5. **Ошибка входа** — повреждение, защита паролем, неверный/неподдерживаемый формат.

Иерархия информации:
1. Что выбрать.
2. Что выбрано.
3. Что происходит.
4. Чем закончилось.
5. Где результат.
6. Что проверить, если есть предупреждения.

## Task Flows

### FLOW-01 — Главный сценарий Word → Excel
Источник: SCENARIO-01, REQ-001…REQ-009, QREQ-001…QREQ-005.

Пользователь: локальный пользователь.  
Цель: получить рабочий `.xlsx` из одного `.doc` или `.docx`.

Шаги:
1. Программа открывается в состоянии выбора Word-файла.
2. Пользователь выбирает файл кнопкой или перетаскивает его в окно.
3. Интерфейс показывает выбранный файл.
4. Пользователь нажимает `Преобразовать в Excel`.
5. Интерфейс показывает `Преобразование...` без выдуманного процента.
6. После обработки появляется `Готово`, `Готово с предупреждениями` или `Не удалось преобразовать`.
7. При успехе показываются имя результата и `Открыть папку`.
8. Пользователь может выбрать `Преобразовать другой файл`.

Прерывание: если приложение закрыто до подтверждённого завершения, незавершённый результат не считается успешным.  
Re-entry: MVP не обязан восстанавливать незавершённую сессию; пользователь запускает программу и выбирает исходник заново.  
Отмена: отдельная кнопка Cancel не обязательна до появления evidence длительной обработки.  
Completion evidence: явный текстовый статус + фактическое имя и расположение результата.

### FLOW-02 — Сложная таблица / неоднозначная нормализация
Источник: SCENARIO-02, REQ-004…REQ-006, QREQ-001.

1. Пользователь запускает обычную конвертацию.
2. Сложная структура обрабатывается автоматически.
3. Если её можно нормализовать без неотмеченной потери данных — процесс завершается нормально.
4. Если часть структуры неоднозначна — Excel может быть создан, но итог становится `Готово с предупреждениями`.
5. Предупреждение объясняет, что именно требует проверки, насколько это можно определить надёжно.

### FLOW-03 — Неподдерживаемый объект
Источник: SCENARIO-03, REQ-008, REQ-009.

1. Таблицы и обычный текст обрабатываются.
2. Неподдерживаемый объект, например изображение, не переносится.
3. Итог: `Готово с предупреждениями`.
4. Пользователь видит, что именно было найдено и пропущено.

### FLOW-04 — Вход нельзя обработать
Источник: SCENARIO-04, REQ-010.

1. Программа обнаруживает неприемлемый вход.
2. Не показывает ложный успех.
3. Объясняет категорию причины: защищён, повреждён, не поддерживается.
4. Предлагает `Выбрать другой файл`.

## Surface Map

### SURFACE-01 — Главное окно
Назначение: провести весь сценарий от выбора Word до результата.  
Главное действие зависит от состояния: `Выбрать Word-файл` → `Преобразовать в Excel` → `Открыть папку` / `Преобразовать другой файл`.

### SURFACE-02 — Системный выбор файла
Назначение: альтернатива drag & drop и ожидаемый keyboard/pointer способ выбора.  
Фильтр: `.doc`, `.docx`.

### SURFACE-03 — Детали предупреждений
Назначение: показывать редкую диагностическую информацию без перегрузки главного результата.  
Вход: `Показать детали` из состояния `Готово с предупреждениями`.

## State / Recovery Model

### STATE-INITIAL
Текст: `Перетащите документ Word сюда или выберите файл`  
Подсказка: `Поддерживаются .doc и .docx`  
Действие: `Выбрать Word-файл`.

### STATE-FILE-SELECTED
Показывается имя файла и кнопка `Преобразовать в Excel`. Есть вторичное действие `Выбрать другой`.

### STATE-PROCESSING
Текст: `Преобразование...`  
Допустимая строка: `Исходный Word-файл не изменяется.`  
Не показывать фиктивный процент выполнения.

### STATE-SUCCESS
Текст: `Готово`  
Показываются имя `.xlsx` и место сохранения.  
Действия: `Открыть папку`, `Преобразовать другой файл`.

### STATE-PARTIAL
Текст: `Готово с предупреждениями`  
Краткое объяснение + `Показать детали`.  
Также доступны `Открыть папку` и `Преобразовать другой файл`.

### STATE-ERROR-FORMAT
`Этот файл не поддерживается. Выберите документ Word в формате .doc или .docx.`

### STATE-ERROR-PROTECTED
`Документ защищён и не может быть преобразован. Исходный файл не изменён.`

### STATE-ERROR-CORRUPT
`Не удалось прочитать документ. Файл может быть повреждён или иметь неподдерживаемую структуру. Исходный файл не изменён.`

### STATE-ERROR-SAVE
`Не удалось сохранить Excel-файл.`  
Если причина известна, показать обычным языком: нет доступа / папка недоступна / носитель недоступен.  
Recovery: выбрать другое место сохранения и повторить сохранение/операцию.

### STATE-INTERRUPTED
Незавершённая сессия не восстанавливается в MVP. Исходный Word остаётся неизменным, пользователь повторяет конвертацию.

## Consequential Content

Интерфейс использует бытовые слова. Пользователь не должен видеть `normalization`, `parser`, `schema`, `validation pipeline` и подобные внутренние термины.

Начальное состояние:
- `Word → Excel`
- `Перетащите сюда документ Word`
- `или выберите файл`
- `Поддерживаются .doc и .docx`
- `[ Выбрать Word-файл ]`

После выбора:
- `Выбран файл: <имя.docx>`
- `[ Преобразовать в Excel ]`
- `Выбрать другой`

Обработка:
- `Преобразование...`
- `Исходный Word-файл не изменяется.`

Успех:
- `Готово`
- `Excel-файл создан: <имя.xlsx>`
- `[ Открыть папку ]`
- `Преобразовать другой файл`

Частичный результат:
- `Готово с предупреждениями`
- пример: `Excel-файл создан, но в документе найден объект, который не переносится: изображение.`
- пример: `Excel-файл создан, но часть сложной структуры таблицы требует проверки.`

## Cognitive Load / Interruption / Re-entry

Пользователь не должен выбирать:
- как обрабатывать числа;
- как обрабатывать даты;
- как нормализовать объединённые/разделённые ячейки;
- какие таблицы извлекать;
- сохранять ли обычный текст;
- переносить ли изображения;
- какой механизм конвертации использовать.

Progressive disclosure:
- сразу видны выбор файла, выбранный файл, основное действие, статус и результат;
- детали предупреждений раскрываются только при необходимости.

## Output Location / Naming UX

UX-РЕШЕНИЕ: по умолчанию результат сохраняется рядом с исходным Word-файлом.

Базовое ожидаемое имя:
`ИсходноеИмя.xlsx`

Если такое имя уже занято, предпочтительно не перезаписывать существующий Excel молча, а использовать безопасное уникальное имя вроде `ИсходноеИмя (1).xlsx`. После завершения интерфейс показывает фактическое имя.

Если сохранить рядом невозможно, пользователь получает понятную ошибку и возможность выбрать доступную папку.

## Responsive / Reflow / Input Behavior

Продукт — Windows desktop utility. Отдельный mobile UX не требуется.

- Pointer: drag & drop + кнопка выбора файла.
- Keyboard: ключевые действия доступны без мыши.
- Длинное имя файла не должно вытеснять основные действия; полное имя остаётся доступным.
- При увеличении системного масштаба/текста статус, основная кнопка и ошибка не должны исчезать.

## Accessibility Requirements

1. Итог не передаётся только цветом.
2. Все главные действия имеют текстовые labels.
3. Drag & drop не является единственным способом выбора.
4. Keyboard focus идёт в логическом порядке.
5. Ошибка содержит причину/категорию и следующий шаг.
6. Disabled-state понятен не только цветом.
7. Анимация не является единственным индикатором обработки.
8. Не использовать фиктивный progress.

## UX Evidence / Аналоги

### ANALOG-01 — PDF24 Converter / PDF24 Creator
Источники:
- https://tools.pdf24.org/en/pdf-converter
- https://tools.pdf24.org/en/creator

НАБЛЮДЕНО: PDF24 использует простой flow выбора/drag & drop файла, запуска conversion и сохранения результата. Desktop Creator работает offline и использует drag & drop.

Что берём:
- drag & drop + file picker;
- явное основное действие;
- минимальное число этапов;
- локальную/offline модель.

Что не берём:
- каталог множества инструментов;
- режимы конвертации;
- online-upload;
- batch UI.

### ANALOG-02 — HandBrake
Источники:
- https://handbrake.fr/docs/en/latest/introduction/quick-start.html
- https://handbrake.fr/docs/en/1.9.0/workflow/start-encoding.html

НАБЛЮДЕНО: HandBrake позволяет выбрать Source кнопкой или drag & drop, показывает Destination, использует явный Start, показывает progress и сообщает о завершении.

Что берём:
- выбранный source видим;
- destination/result не скрыт;
- отдельное processing-state;
- явный completion.

Что не берём:
- presets;
- очередь;
- advanced controls.

### ANALOG-03 — File Converter
Источник: https://file-converter.io/

НАБЛЮДЕНО: File Converter сводит операции к Windows Explorer context menu и позиционирует интерфейс как максимально лёгкий. Для Office-документов официальный сайт указывает зависимость от установленного Microsoft Office.

Что полезно:
- короткий converter workflow.

Что не берём:
- обязательную Explorer shell integration;
- context-menu-only основной сценарий;
- зависимость от Office.

## Рассмотренные Interaction Alternatives

### ВАРИАНТ A — Одно окно, выбрать/перетащить → явная кнопка `Преобразовать`
Плюсы: понятно, виден выбранный файл, работает с мышью и клавиатурой, удобно показывать warnings/errors, подходит portable-сценарию.  
Минус: один дополнительный клик.  
Решение: **ВЫБРАНО для MVP**.

### ВАРИАНТ B — Автоконвертация сразу после drop
Плюс: минимальное число действий.  
Минусы: меньше контроля, хуже заметен ошибочно выбранный файл, сложнее объяснить destination/recovery.  
Решение: не выбран; возможен позже как quick mode при реальной потребности.

### ВАРИАНТ C — Context menu / drag прямо на EXE
Плюс: очень быстро для частого использования.  
Минусы: context-menu integration хуже соответствует portable без установки, drag-on-EXE плохо discoverable, предупреждения и recovery менее очевидны.  
Решение: не выбран для MVP.

## Выбранные UX-решения

1. Одно основное окно, без wizard.
2. Drag & drop и системный file picker.
3. Выбранный файл показывается до старта.
4. Явная кнопка `Преобразовать в Excel`.
5. Нет пользовательских настроек конвертации в MVP.
6. Processing-state без выдуманного процента.
7. Три явных итога: успех / предупреждения / ошибка.
8. Подробности warnings раскрываются по требованию.
9. После результата показываются фактическое имя и `Открыть папку`.
10. Не полагаться на автоматическое открытие Excel.
11. Результат по умолчанию рядом с исходником.
12. При конфликте имени — безопасное уникальное имя вместо молчаливой перезаписи.
13. Если сохранить рядом нельзя — предложить другую папку.
14. После результата — `Преобразовать другой файл`.
15. Незавершённая сессия не требует resume в MVP.
16. OCR, batch и дополнительные converter modes отсутствуют в MVP.

## Usability Risks / Что проверить позже

Реальных usability sessions и аналитики пока нет.

- **RISK-UX-01:** пользователь может ожидать auto-start после drop. Проверить на Product Test; пока оставляем явную кнопку как защиту от ошибочного выбора.
- **RISK-UX-02:** `Готово с предупреждениями` может быть понято неверно. Проверить, понимает ли пользователь: Excel создан, им можно пользоваться, но конкретные элементы требуют проверки.
- **RISK-UX-03:** пользователь может не понять, где сохранён файл. Защита: показывать имя и `Открыть папку`.
- **RISK-UX-04:** длинные имена файлов. Проверить reflow на очень длинном имени.
- **RISK-UX-05:** десятки warnings могут перегрузить окно. Текущий UX: краткое резюме + детали; группировку вводить только при реальных примерах.
- **RISK-UX-06:** длительная обработка. Если замеры покажут реальную задержку, может понадобиться честный progress и cancel.

## Подтверждено

- Один Word → один рабочий Excel.
- `.doc` и `.docx` обязательны.
- Один файл за один запуск.
- Молчаливая потеря/изменение данных недопустимы.
- Рабочая Excel-структура важнее визуального копирования Word.
- Каждая Word-таблица становится отдельным Excel-листом.
- Обычный текст сохраняется отдельно от рабочих таблиц.
- Неподдерживаемые изображения/объекты вызывают предупреждение.
- Пользователь различает полный успех, предупреждения и ошибку.
- Word, Excel и интернет не являются обязательными runtime-зависимостями.
- OCR и batch не входят в MVP.
- Исходный Word не изменяется.

## Наблюдено

- PDF24 использует зрелый pattern выбора/drag & drop файла с последующим conversion и сохранением результата.
- PDF24 Creator использует drag & drop и работает локально/offline.
- HandBrake позволяет выбрать source через file picker или drag & drop, показывает destination, использует явный Start, progress и completion.
- File Converter минимизирует converter workflow через Explorer context menu, но для Office-документов официальный сайт указывает обязательный Microsoft Office.

## Гипотезы

- Одно окно проще wizard для этого MVP.
- Явная кнопка `Преобразовать` полезнее auto-start в первой версии.
- Сохранение результата рядом с исходником уменьшит поиск файла.
- `Открыть папку` лучше автоматического открытия `.xlsx`, поскольку Excel может отсутствовать.
- Детали warnings лучше раскрывать по запросу.
- Cancel не нужен, пока processing не доказан как длительный.

## Неизвестно / Не проверено

- Реальная частота warnings/errors на пользовательских документах.
- Типичная длительность преобразования.
- Нужен ли cancel и точный progress.
- Частота конфликтов имён `.xlsx`.
- Реальная понятность формулировки `с предупреждениями`.
- Нужна ли группировка warnings по таблицам.
- Реальная keyboard/accessibility usability.
- Реальные usability sessions и analytics отсутствуют.

## Ограничения исследования

- UX research основан на официальной документации и публично описанном поведении аналогов, а не на полевых usability tests.
- Не выдумывались частота, analytics или результаты тестирования.
- Visual design не выполнялся: wireframes фиксируют только hierarchy и flow.
- Framework, architecture, libraries и packaging не выбирались.
- Технические способы recovery и progress принадлежат Фазе 06.
