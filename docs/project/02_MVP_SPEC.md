# 02 — MVP Specification

PHASE: 02_MVP_SPEC  
STATUS: COMPLETE

## Источники

- `01_PROJECT_INTENT.md`
- Microsoft Support — Copy a Word table into Excel
- Microsoft Support — Keeping leading zeros and large numbers
- Microsoft Support — Merge or split cells in a table
- Microsoft Support — Split a cell in Excel
- Microsoft Support — Protect a Word document with a password

## Цель MVP

Создать первую полезную версию portable-инструмента для Windows, который принимает один файл Microsoft Word (`.doc` или `.docx`) и создаёт один рабочий Excel-файл (`.xlsx`) без обязательного наличия Microsoft Word, Microsoft Excel или интернета.

Главная ценность MVP: пользователь получает Excel, в котором табличные данные сохранены без молчаливых потерь, каждая исходная таблица доступна как отдельная рабочая таблица/лист, а структура при необходимости нормализована под обычную сетку Excel.

## Основной пользователь

Пользователь, которому передают Word-документы, но дальнейшая работа с содержащимися в них таблицами должна выполняться в Excel.

Первая версия ориентирована на одного локального пользователя и не требует учётных записей, команд, ролей или сетевой инфраструктуры.

## Success Criteria

### SC-001 — Главный сценарий выполняется без ручного переноса данных

Пользователь может передать программе один поддерживаемый Word-файл и получить один `.xlsx`, не копируя содержимое таблиц вручную.

### SC-002 — Все поддерживаемые табличные данные сохранены

Для каждой поддерживаемой таблицы из входного Word-файла в выходном Excel присутствует соответствующая таблица/лист, а содержимое исходных ячеек не теряется и не изменяется молча.

### SC-003 — Результат пригоден для обычной работы в Excel

Табличные листы имеют нормальную прямоугольную структуру и не загрязнены внешним текстом документа так, чтобы это мешало сортировке, фильтрации, формулам и построению сводных таблиц.

### SC-004 — Неоднозначность не маскируется под успех

Если часть входного документа невозможно перенести без риска изменения или потери, пользователь получает явное предупреждение о проблемном элементе; результат не объявляется полностью успешным без такого сообщения.

### SC-005 — Инструмент автономен

Главный сценарий MVP работает на Windows без обязательного установленного Microsoft Word, Microsoft Excel и без обязательного интернет-соединения.

## Границы MVP

### Входит

- Один входной файл за один запуск.
- Входные форматы `.doc` и `.docx`.
- Выходной формат `.xlsx`.
- Извлечение всех редактируемых Word-таблиц из поддерживаемого документа.
- Каждая отдельная Word-таблица — отдельный лист Excel.
- Нормализация сложной Word-структуры в прямоугольную Excel-сетку.
- Сохранение содержимого ячеек без молчаливого изменения.
- Безопасное представление кодов, длинных числовых последовательностей, значений с ведущими нулями и других данных, которые Excel может автоматически изменить.
- Сохранение обычного текстового содержимого документа отдельно от рабочих табличных листов.
- Явное сообщение о найденных, но не перенесённых изображениях, логотипах, схемах и иных неподдерживаемых объектах.
- Явное сообщение об ошибке/неполном результате.
- Работа без обязательного Word, Excel и интернета.
- Portable-сценарий: приложение может быть передано на флешке и запущено без обязательной установки дополнительных пользовательских программ.

### Не входит

- OCR фотографий или сканов таблиц.
- Преобразование изображения таблицы в Excel.
- Полное визуальное воспроизведение Word-документа в Excel.
- Сохранение Word-оформления ценой ухудшения структуры рабочих данных.
- Пакетная обработка нескольких Word-файлов за один запуск.
- Универсальная конвертация других офисных форматов.
- Редактирование исходного Word-файла.
- Облачное хранение, аккаунты, синхронизация и совместная работа.

### Позже

- OCR сканов/фотографий таблиц.
- Пакетная обработка нескольких файлов.
- Расширение поддержки дополнительных нетабличных объектов, если появится реальная потребность.

## Пользователи / роли

### ROLE-01 — Локальный пользователь

Кто это: человек, которому нужен Excel вместо полученного Word-документа.

Цель: преобразовать один Word-файл в рабочий Excel без ручного переноса данных.

Необходимые действия MVP:
- предоставить один `.doc` или `.docx`;
- запустить преобразование;
- получить `.xlsx`;
- увидеть, прошло ли преобразование полностью или есть предупреждения/ошибки.

Дополнительных ролей в MVP нет.

## Пользовательские сценарии

### SCENARIO-01 — Успешное преобразование одного Word-файла

Пользователь: локальный пользователь.  
Цель: получить рабочий Excel из Word-документа.  
Предусловия: доступен читаемый `.doc` или `.docx`, содержащий одну или несколько редактируемых таблиц.  
Триггер: пользователь передаёт файл программе и запускает преобразование.  
Основной ход:
1. Программа принимает файл.
2. Определяет таблицы и обычный текстовый контент.
3. Создаёт один `.xlsx`.
4. Для каждой Word-таблицы создаёт отдельный табличный лист.
5. При необходимости нормализует структуру таблицы под Excel.
6. Сохраняет обычный текст отдельно от рабочих таблиц.
7. Проверяет, что неподдерживаемые или неоднозначные элементы не были молча проигнорированы.
8. Сообщает итоговый статус.

Ожидаемый результат: создан `.xlsx`, табличные данные доступны для обычной работы в Excel, отсутствуют неотмеченные потери.  
Критичный альтернативный исход: если часть содержимого нельзя перенести корректно, пользователь получает предупреждение с указанием проблемы.

### SCENARIO-02 — Документ содержит сложную Word-таблицу

Пользователь: локальный пользователь.  
Цель: получить рабочую Excel-структуру без потери содержимого.  
Предусловия: Word-таблица содержит объединённые/разделённые ячейки или иную структуру, которую нельзя напрямую представить как идентичную Excel-сетку.  
Триггер: преобразование документа.  
Основной ход:
1. Программа сохраняет содержимое исходных ячеек.
2. Структура нормализуется в прямоугольную сетку.
3. Нормализация не должна молча уничтожать значения.
4. Если однозначная нормализация невозможна, это отражается в предупреждении.

Ожидаемый результат: данные сохранены, итоговая таблица пригодна для работы в Excel.  
Критичный альтернативный исход: невозможно однозначно разместить часть данных — результат маркируется как требующий проверки.

### SCENARIO-03 — Документ содержит неподдерживаемый объект

Пользователь: локальный пользователь.  
Цель: понять, что именно не было перенесено.  
Предусловия: документ содержит изображение, логотип, схему или иной объект, не входящий в поддерживаемый MVP-контент.  
Триггер: преобразование документа.  
Основной ход:
1. Поддерживаемый текст и таблицы преобразуются.
2. Неподдерживаемый объект не переносится.
3. Пользователь получает явное предупреждение о его наличии.

Ожидаемый результат: нет ложного сообщения о полном переносе документа.

### SCENARIO-04 — Вход нельзя корректно обработать

Пользователь: локальный пользователь.  
Цель: получить понятный отказ вместо ложного Excel-результата.  
Предусловия: файл повреждён, зашифрован паролем, имеет неверное расширение/формат или не может быть прочитан.  
Триггер: попытка преобразования.  
Основной ход:
1. Программа обнаруживает невозможность надёжной обработки.
2. Не объявляет преобразование успешным.
3. Сообщает пользователю причину или понятную категорию ошибки.

Ожидаемый результат: пользователь понимает, что вход не был корректно преобразован.

## Функциональные требования

### REQ-001 — Приём одного Word-файла

Требование: MVP должен принимать один файл `.doc` или `.docx` за один запуск.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-001-1

Дано: пользователь предоставляет один читаемый `.doc`.  
Когда: запускается преобразование.  
Тогда: файл принимается как поддерживаемый вход.

#### AC-001-2

Дано: пользователь предоставляет один читаемый `.docx`.  
Когда: запускается преобразование.  
Тогда: файл принимается как поддерживаемый вход.

### REQ-002 — Создание одного Excel-файла

Требование: для одного принятого Word-файла MVP должен создавать один `.xlsx`.  
Источник: INTENT.

#### AC-002-1

Дано: поддерживаемый Word-файл успешно обработан.  
Когда: преобразование завершено.  
Тогда: пользователь получает один открываемый `.xlsx`.

### REQ-003 — Отдельный лист для каждой Word-таблицы

Требование: каждая отдельная редактируемая таблица Word должна быть представлена отдельным листом Excel.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-003-1

Дано: Word-документ содержит N поддерживаемых таблиц.  
Когда: преобразование успешно.  
Тогда: в `.xlsx` присутствуют N отдельных табличных листов, каждый соответствующий одной исходной таблице.

### REQ-004 — Нормализация структуры под Excel

Требование: если структура Word-таблицы не является прямоугольной Excel-сеткой, MVP должен преобразовать её в рабочую прямоугольную структуру, сохранив содержимое исходных ячеек.  
Источник: USER_CONFIRMATION / ANALOG_EVIDENCE.

#### AC-004-1

Дано: Word-таблица содержит объединённые или разделённые ячейки.  
Когда: структура может быть нормализована без потери содержимого.  
Тогда: Excel-лист имеет прямоугольную сетку, а исходное содержимое присутствует в результате.

#### AC-004-2

Дано: однозначная нормализация части таблицы невозможна.  
Когда: выполняется преобразование.  
Тогда: программа не скрывает проблему и выдаёт предупреждение о необходимости проверки.

### REQ-005 — Сохранение данных без молчаливого изменения

Требование: MVP не должен молча изменять отображаемое/значимое содержимое исходных табличных данных.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-005-1

Дано: ячейка Word содержит `001234`.  
Когда: документ преобразован.  
Тогда: пользователь видит в Excel `001234`, а не `1234`.

#### AC-005-2

Дано: ячейка содержит цифровую последовательность, которую Excel не способен безопасно хранить как обычное число без потери точности.  
Когда: документ преобразован.  
Тогда: последовательность сохраняется без изменения цифр.

#### AC-005-3

Дано: ячейка содержит текстовое значение.  
Когда: документ преобразован.  
Тогда: текст не изменён молча.

### REQ-006 — Рабочие типы данных при отсутствии риска потери

Требование: значения могут быть представлены в Excel как число/дата только тогда, когда это не изменяет значимое исходное содержимое; при риске изменения приоритет имеет точное сохранение данных.  
Источник: USER_CONFIRMATION / ANALOG_EVIDENCE.

#### AC-006-1

Дано: значение может быть представлено в Excel как число или дата без изменения значимого исходного значения.  
Когда: документ преобразован.  
Тогда: результат допускает стандартные операции Excel над этим значением.

#### AC-006-2

Дано: преобразование в числовой/датовый тип может изменить исходные данные или их значимое представление.  
Когда: документ преобразован.  
Тогда: значение сохраняется в форме, исключающей такую потерю.

### REQ-007 — Сохранение обычного текста отдельно от таблиц

Требование: обычный текст Word-документа, относящийся к содержимому документа, должен сохраняться в `.xlsx` отдельно от рабочих табличных листов.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-007-1

Дано: Word-документ содержит заголовки, обычные абзацы, подписи или примечания вне таблиц.  
Когда: документ преобразован.  
Тогда: этот текст доступен в итоговом `.xlsx` и не вставлен внутрь рабочих диапазонов таблиц таким образом, чтобы мешать их обычной обработке.

### REQ-008 — Явное предупреждение о неподдерживаемых объектах

Требование: изображения, логотипы, схемы и иные нетабличные объекты, не поддерживаемые MVP, могут быть пропущены только с явным предупреждением.  
Источник: USER_CONFIRMATION.

#### AC-008-1

Дано: Word-документ содержит изображение.  
Когда: изображение не переносится в `.xlsx`.  
Тогда: пользователь получает сообщение, что в документе найден и не перенесён неподдерживаемый объект.

### REQ-009 — Понятный итоговый статус

Требование: после обработки пользователь должен получить один из наблюдаемых итогов: успешное преобразование, преобразование с предупреждениями либо ошибка.  
Источник: INTENT / PROPOSED_REQUIREMENT.

#### AC-009-1

Дано: все поддерживаемые данные перенесены и проблем не обнаружено.  
Когда: обработка завершена.  
Тогда: результат обозначен как успешный.

#### AC-009-2

Дано: `.xlsx` создан, но обнаружены неподдерживаемые/неоднозначные элементы.  
Когда: обработка завершена.  
Тогда: результат обозначен как выполненный с предупреждениями.

#### AC-009-3

Дано: вход нельзя надёжно обработать.  
Когда: обработка прекращена.  
Тогда: результат обозначен как ошибка, а не успех.

### REQ-010 — Отказ на неприемлемом входе

Требование: повреждённый, зашифрованный паролем или фактически неподдерживаемый вход не должен приводить к ложному успешному `.xlsx`.  
Источник: ANALOG_EVIDENCE / PROPOSED_REQUIREMENT.

#### AC-010-1

Дано: Word-документ зашифрован паролем и не может быть прочитан автоматически.  
Когда: пользователь запускает преобразование.  
Тогда: программа сообщает, что файл нельзя обработать в текущем виде, и не заявляет успешное полное преобразование.

#### AC-010-2

Дано: файл повреждён или его содержимое не соответствует поддерживаемому Word-формату.  
Когда: запускается преобразование.  
Тогда: программа завершает операцию с ошибкой и не выдаёт ложный статус успеха.

## Quality / Non-Functional Requirements

### QREQ-001 — Нулевая допустимая молчаливая потеря поддерживаемых данных

Требование: допустимое количество необозначенных потерь или необозначенных изменений поддерживаемого текстового/табличного содержимого — 0.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-Q001-1

Дано: набор тестовых документов с известным исходным содержимым.  
Когда: выполняется преобразование и сверка поддерживаемых данных.  
Тогда: каждое расхождение либо отсутствует, либо явно отражено как предупреждение/ошибка; необозначенных расхождений нет.

### QREQ-002 — Приоритет сохранности над автоматической типизацией

Требование: если между автоматическим превращением значения в рабочий Excel-тип и точным сохранением исходных данных есть конфликт, MVP должен выбирать сохранение исходных данных.  
Источник: USER_CONFIRMATION.

#### AC-Q002-1

Дано: вход содержит код с ведущими нулями или числовую последовательность, для которой Excel может изменить значение.  
Когда: выполняется преобразование.  
Тогда: итог сохраняет исходное значение полностью.

### QREQ-003 — Автономная работа

Требование: выполнение главного сценария не должно требовать установленного Microsoft Word, Microsoft Excel или активного интернет-соединения.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-Q003-1

Дано: поддерживаемый Windows-компьютер без установленного Microsoft Office и без доступа к интернету.  
Когда: пользователь запускает преобразование поддерживаемого файла.  
Тогда: главный сценарий может быть завершён и `.xlsx` создан.

### QREQ-004 — Исходный Word-файл не изменяется

Требование: преобразование не должно изменять содержимое исходного Word-файла.  
Источник: PROPOSED_REQUIREMENT, необходимое следствие безопасного конвертера.

#### AC-Q004-1

Дано: исходный файл до преобразования.  
Когда: преобразование завершено или завершилось ошибкой.  
Тогда: исходный файл остаётся неизменным по содержимому.

### QREQ-005 — Переносимость

Требование: пользовательский сценарий должен быть пригоден для запуска программы с переносного носителя без обязательной установки дополнительного пользовательского ПО.  
Источник: USER_CONFIRMATION / INTENT.

#### AC-Q005-1

Дано: программа находится на переносном носителе на поддерживаемом Windows-компьютере.  
Когда: пользователь запускает её.  
Тогда: для выполнения главного сценария не требуется отдельно устанавливать Word, Excel или иной офисный пакет.

## Входы

### Поддерживаемый вход

- Один файл `.doc`.
- Один файл `.docx`.
- Файл должен быть читаемым и доступным программе.
- Таблицы должны быть реальными редактируемыми Word-таблицами, а не только изображениями/сканами.

### Неприемлемый / ограниченный вход

- Повреждённый файл.
- Зашифрованный/закрытый паролем документ, который нельзя прочитать без разблокировки.
- Файл с расширением `.doc`/`.docx`, фактически не являющийся поддерживаемым Word-документом.
- Таблицы, существующие только как изображения, не распознаются OCR в MVP.

При неприемлемом входе не допускается ложный статус полного успеха.

## Выходы

### Основной выход

Один `.xlsx`, содержащий:

- отдельный табличный лист для каждой поддерживаемой Word-таблицы;
- сохранённый отдельно обычный текстовый контент документа;
- рабочую Excel-структуру, не зависящую от визуального макета Word.

### Статус преобразования

Один из трёх продуктовых исходов:

- УСПЕХ — поддерживаемое содержимое перенесено, необработанных проблем не обнаружено;
- С ПРЕДУПРЕЖДЕНИЯМИ — Excel создан, но найдены неподдерживаемые или неоднозначные элементы;
- ОШИБКА — надёжное преобразование входа невозможно.

## Важные edge cases

1. **Ведущие нули** — `001234` не должен превращаться в `1234`.
2. **Длинные цифровые последовательности** — не должны терять цифры из-за ограничений точности Excel.
3. **Значения, похожие на даты** — не должны автоматически менять смысл или отображаемое значение.
4. **Объединённые/разделённые Word-ячейки** — требуют нормализации без потери содержимого.
5. **Разное логическое количество ячеек в строках Word** — должно приводиться к рабочей прямоугольной структуре либо маркироваться как неоднозначное.
6. **Несколько таблиц в одном документе** — каждая должна попасть на отдельный лист.
7. **Текст до, между и после таблиц** — сохраняется отдельно, не загрязняя рабочие диапазоны.
8. **Изображения/логотипы/схемы** — не переносятся в MVP, но всегда отражаются предупреждением.
9. **Документ без таблиц** — не должен создавать впечатление, что табличные данные успешно извлечены; обычный текст может быть сохранён, итоговый статус должен отражать отсутствие таблиц.
10. **Пустые таблицы/пустые ячейки** — не должны приводить к сдвигу соседних данных.
11. **Пароль/шифрование** — понятный отказ, если содержимое нельзя прочитать.
12. **Повреждённый файл** — ошибка вместо частичного молчаливого результата.

## Product Assumptions / Dependencies

### ASSUMPTION-001

Предположение: значительная часть реальных входных документов содержит настоящие редактируемые Word-таблицы.  
Почему важно: OCR исключён из MVP.  
Подтверждено: ЧАСТИЧНО — текущий пользовательский сценарий основан именно на таких документах.  
Если ложно: ценность MVP снизится, потребуется возвращение к scope и возможное добавление OCR.

### ASSUMPTION-002

Предположение: пользователь считает «данными» прежде всего видимое текстовое/табличное содержимое документа; сложное визуальное оформление Word вторично.  
Почему важно: нормализация структуры разрешена, визуальная идентичность не является целью.  
Подтверждено: ДА.  
Если ложно: потребуется менять intent и возвращаться в Фазу 01.

### ASSUMPTION-003

Предположение: поддерживаемый Windows-компьютер позволяет запускать portable-приложение с внешнего носителя.  
Почему важно: это часть пользовательского сценария передачи инструмента на флешке.  
Подтверждено: ДА как продуктовая потребность; конкретные версии Windows и системные ограничения ещё не определены.  
Если ложно: техническая реализация portable-сценария потребует пересмотра.

## Продуктовые ограничения

- Только Windows как подтверждённая целевая пользовательская среда.
- Один файл за один запуск.
- Только `.doc` и `.docx` на входе.
- Только `.xlsx` как целевой табличный результат.
- Никакого обязательного Office.
- Никакого обязательного интернета.
- Никакого OCR в первой версии.
- Приоритет: сохранность данных > визуальная идентичность Word.
- Нормализация структуры разрешена только при сохранении данных или явной маркировке невозможности корректного переноса.

## Термины

**Рабочий Excel** — `.xlsx`, в котором каждая исходная таблица представлена отдельно и данные организованы в обычной Excel-сетке, пригодной для сортировки, фильтрации, формул и сводных таблиц.

**Сохранение данных** — отсутствие молчаливой потери или молчаливого изменения значимого текстового/табличного содержимого входного Word-документа.

**Нормализация** — преобразование Word-структуры, не имеющей прямого эквивалента в Excel, в прямоугольную сетку без скрытой потери содержимого.

**Неподдерживаемый объект** — элемент документа, который MVP не обязан переносить в Excel (например, изображение), но обязан обнаружить и обозначить пользователю, если он найден.

## Аналоги и влияние на спецификацию

### Аналог 1

Название: Microsoft Word → Excel Copy/Paste  
Источник: Microsoft Support — Copy a Word table into Excel.

Что подтверждает:
- Word-ячейки могут переноситься в отдельные Excel-ячейки;
- после обычной вставки могут возникнуть проблемы с лишними пробелами, числами как текстом и отображением дат.

Что ставит под сомнение:
- идея, что простого механического переноса достаточно для получения рабочего Excel.

Что НЕ переносим:
- ручной copy/paste как основной пользовательский сценарий;
- требование сохранять Word-оформление любой ценой.

Влияние на MVP:
- нужен автоматический перенос;
- нужен контроль сохранности и пригодности данных для Excel.

### Аналог 2

Название: Microsoft Excel — правила ведущих нулей и больших чисел  
Источник: Microsoft Support — Keeping leading zeros and large numbers.

Что подтверждает:
- Excel может удалять ведущие нули;
- большие числовые коды могут переводиться в научную нотацию;
- Excel имеет ограничение числовой точности, поэтому некоторые цифровые последовательности необходимо хранить как текст для сохранения исходных цифр.

Что ставит под сомнение:
- требование «всё похожее на число автоматически превращать в число».

Что НЕ переносим:
- автоматическую типизацию любой ценой.

Влияние на MVP:
- сохранность исходного значения имеет приоритет;
- небезопасные цифровые значения должны сохраняться без изменения.

### Аналог 3

Название: Microsoft Word / Excel — различие структуры таблиц  
Источник: Microsoft Support — Merge or split cells in a table; Split a cell in Excel.

Что подтверждает:
- Word позволяет объединять и разделять ячейки;
- Excel не поддерживает разделение одной ячейки так же, как Word.

Что ставит под сомнение:
- возможность всегда переносить структуру Word один в один.

Что НЕ переносим:
- требование полной структурной идентичности Word и Excel.

Влияние на MVP:
- нормализация сложных Word-таблиц — обязательная часть продуктового поведения.

### Аналог 4

Название: Microsoft Word password protection  
Источник: Microsoft Support — Protect a Word document with a password.

Что подтверждает:
- Word-документы могут быть зашифрованы паролем и требовать пароль для открытия.

Что ставит под сомнение:
- предположение, что любой файл с расширением `.doc/.docx` всегда можно прочитать автоматически.

Что НЕ переносим:
- функцию обхода/восстановления паролей.

Влияние на MVP:
- защищённый документ является важным отказным сценарием, если его нельзя прочитать в текущем виде.

## Предложенные, но не подтверждённые требования

- Конкретный способ отображения предупреждений.
- Конкретный UX передачи файла программе.
- Конкретный формат листа с обычным текстом.
- Автоматическое именование листов.
- Числовые ограничения на максимальный размер Word-файла, число таблиц, строк или столбцов.
- Ограничение по времени преобразования.
- Поддержка ввода пароля для защищённого документа.

Эти вопросы не блокируют продуктовую спецификацию MVP и относятся к UX или техническим фазам либо требуют реальных данных о нагрузке.

## Подтверждено

- Нужен собственный Word → Excel инструмент.
- `.doc` и `.docx` обязательны.
- `.xlsx` — обязательный результат.
- Один Word-файл за один запуск.
- Каждая Word-таблица → отдельный Excel-лист.
- Excel должен быть рабочим для сортировки, фильтрации, формул и сводных таблиц.
- Данные должны сохраняться полностью; молчаливые потери недопустимы.
- Сложную Word-структуру разрешено нормализовать.
- При конфликте сохранности и автоматической типизации приоритет у сохранности.
- Обычный текст документа сохраняется отдельно от рабочих таблиц.
- Картинки/схемы/логотипы не переносятся в MVP, но их пропуск обозначается.
- OCR не входит в MVP.
- Работа без Microsoft Word, Microsoft Excel и интернета обязательна.
- Portable-сценарий обязателен.

## Обнаружено

- Microsoft указывает, что после прямого Word → Excel copy/paste числа могут стать текстом, даты отображаться некорректно, а в данных могут присутствовать лишние пробелы.
- Excel автоматически удаляет ведущие нули у числового текста и имеет ограничение числовой точности для длинных цифровых значений; для сохранения таких кодов требуется текстовое представление.
- Word позволяет свободно объединять и разделять ячейки, тогда как Excel не может разделить одну ячейку тем же способом.
- Word-документы могут быть защищены паролем и недоступны для чтения без него.

## Гипотезы

- Реальные документы пользователя в основном состоят из обычного текста и редактируемых таблиц.
- Конкретный формат предупреждений можно определить в UX-фазе без изменения продуктового смысла.
- Конкретные правила технического определения «безопасной типизации» можно разработать на технической фазе, сохраняя зафиксированный продуктовый приоритет «не изменять данные».

## Неизвестно

- Максимальный реальный размер входных документов.
- Максимальное число таблиц/строк/столбцов в типичных документах.
- Требуемое время обработки.
- Конкретные версии Windows, которые должны считаться поддерживаемыми.
- Конкретный формат листа с обычным текстом.
- Конкретный формат отчёта/предупреждений.
- Как технически обеспечивается чтение `.doc` и `.docx`.
- Как технически обеспечивается автономность без Office.
- Как именно упаковывается portable-приложение.

Эти неизвестные не должны заполняться догадками на Фазе 02.

## Ограничения исследования

- Исследование Фазы 02 было узким и ориентировалось на product behavior и критические edge cases, а не на выбор библиотек или архитектуры.
- Не проводился code audit open-source решений.
- Не проводились нагрузочные тесты на реальных пользовательских документах.
- Не установлен числовой performance/capacity порог, поскольку пользователь его не задавал и фактическая нагрузка неизвестна.
- Техническая реализуемость каждого способа поддержки старого `.doc` без Office относится к Фазе 06.
